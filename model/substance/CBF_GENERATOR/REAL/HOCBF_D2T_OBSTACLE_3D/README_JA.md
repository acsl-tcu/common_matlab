# 3D障害物回避HOCBF：推力2階微分を制御する拡張モデル

2026-11-23 新規研究フォルダ / 既存XY・Sim・HLC・CBF_DISPATCH等への変更 **なし**。

## 置き場所
既存 `CBF_GENERATOR/REAL/XY/` と**同じ階層**に `HOCBF_D2T_OBSTACLE_3D/` を追加する。`WAYPOINT_REFERENCE/` に置くのは別課題の「軌道目標補正器」であり、CBFジェットの生成器は置かない。

## 理論とモデル
元の吊り荷付きドローン19状態 `x=[q(4);omega(3);pL(3);vL(3);pT(3);omegaL(3)]` を変更しない。その外側にスカラー状態 `[T;dT]` を追加した21状態 `y` に対して

```
xdot = f_physical(x,T,tauX,tauY,tauZ)
Tdot = dT
(dT)dot = vT
v = [vT;tauX;tauY], vT = Tddot
```

を仮定する。`tauZ` はHLCのクリップ済み値で固定。`vT,tauX,tauY` は区間内一定とし、推力の時間波形は `T(s)=T0+dT0*s+(1/2)*vT*s^2`。既存Simが採用する「**Tを25ms ZOH**」と**異なるプラント・アクチュエータ仮定**である。従ってこの生成器を単に現在のCBF_ID=2へ差し込んで安全とは言えない。推力時間波形を現実に追従できるアクチュエータか、ZOH推力離散時間CBFの再設計が必要。

3D障害物は球・回転楕円体に対応。保護する幾何は `G.collisionMode` で選ぶ。
- `load_sphere`（**初期設定**）: 吊り荷中心の半径 `G.radius` の球だけを障害物から守る。
- `drone_sphere`: 機体中心 `pL-L*pT` の球。傾斜制約を追加するわけではない。
- `cable_ellipsoid`: 元のXYと同型の `pT` に沿って回転する楕円体（比較用）。ケーブル傾斜制約を追加しない。実索を囲う形状証明は別途必要。

通常動作で `load_sphere` 以外を使う必要はない。**同時に機体・吊り荷・紐を全保護するものではない**。独立した機体傾斜／ケーブル傾斜／地面／入力依存ジオメトリの追加制約は一切含めない。

保護対象の中心C、形状行列Qc、障害物の中心c、楕円体Qobsについて、`d=C-c`, `n=d/||d||` として

```
h(y) = n'*d - sqrt(n'*Qc*n) - sqrt(n'*Qobs*n)
```

を用いる。`h>=0` は二つの楕円体が**分離している十分条件**、`h<0` だけでは衝突を断定できない。`||d||=0` 付近は法線特異点としてエラーにする。障害物は静的・検出結果が有効と仮定する。

各障害物に対して

```
psi0 = h
psii = dot(psi(i-1)) + lambda(i)*psi(i-1) (i=1,...,4)
psi4 = a(y,tauZ)+B_T(y,tauZ)*vT+B_x(y,tauZ)*tauX+B_y(y,tauZ)*tauY >= 0
psi0,psi1,psi2,psi3 >= 0 (初期条件)
```

を課す。`CBF_REAL_D2T_QP_ROWS` は `A*v>=b` の行、低次の現在値、アフィン性監査を作る。同じ拡張状態を固定し、決定変数の単位摂動で係数を組み立てる。これは**1周期で複数回の4階Taylorジェット計算**を要するため、そのままでリアルタイム達成を主張しない。幾何・モデルによってBの行がほぼ0になる、初期低次条件が負になる、3変数の共通QPが空になる場合がある。

**推力限界（改訂）**: 元HLCに合わせて既定値 `0<=T(s)<=20 N` を採用。`T(s)=T0+dT0*s+0.5*vT*s^2`, `0<=s<=dt`、**一定の vT（ddT）** のもとで、区間内全時刻を満たす `vT_min(T0,dT0,dt)<=vT<=vT_max(T0,dT0,dt)` を解析的に厳密に導く。`CBF_REAL_D2T_THRUST_ROWS.m` で上下1行ずつ、QPの線形不等式にする。以前の保守的Bernstein3点判定と異なり、内部で極値を持つ正当な曲線も認める。初期推力が範囲外、または端点で外向きの非零推力速度の場合は、有限の2階微分では安全を回復できないので明示的に不可行とする。

`\ddot T` の実アクチュエータ限界は既存Simに無いため**数値を捏造しない**。QPは推力箱から導かれる有限の範囲だけで動作可能とした。ただし物理実現性は認証されない。実アクチュエータ仕様が判明すれば `cfg.ddTBounds=[min max]` を別途追加可能で、交差集合が空なら不可行。**推力の区間内制約が厳密でも、障害物CBFの25ms区間内安全性は未証明**。

### 区間全体の推力制限からddTを導く式

`r=dT0`, `H=dt`, `L=Tmin`, `U=Tmax` とおく。
`0<s<=H` での下限・上限の要求は次式と同値：

```
ddT >= 2*(L-T0-r*s)/s^2   (全s)
ddT <= 2*(U-T0-r*s)/s^2   (全s)
```

したがって下限は右辺の**最大値**、上限は右辺の**最小値**。各右辺は区間端点 `s=H` と高々1個の停留点を調べるだけで極値が得られる。

```
a_min = 2*(L-T0-r*H)/H^2
a_max = 2*(U-T0-r*H)/H^2
if r<0 and T0>L and 2*(T0-L)/(-r)<H:
    a_min = max(a_min, r^2/(2*(T0-L)))
if r>0 and T0<U and 2*(U-T0)/r<H:
    a_max = min(a_max, -r^2/(2*(U-T0)))
```

境界 `T0=L,r<0` または `T0=U,r>0` は最初の瞬間に箱を出るため、有限ddTでは不可行。`a_min>a_max` も不可行。上式は**指定された定数ddTモデル内で厳密**。区間ごとに計算して毎周期更新できるが、次々周期のCBF可行性まで保証するものではない。

例：`T0=19.5 N`, `r=100 N/s`, `H=0.025 s` では `a_max=-10000 N/s^2`。この加速度で `s=0.01 s` に `T(s)=20 N` の内部極大ができ、その後下降する。一方、元の3点Bernstein条件は中間制御点が20.75 Nのため、**実際には許容されるこの波形を排除**していた。`T0=10 N,r=0` なら `-32000<=ddT<=32000 N/s^2` となるが、これはあくまで数学上の範囲であり実モータの許容加速度を意味しない。

**サンプル間安全**: 瞬時のHOCBF条件が1周期中ずっと成立することは未保証。`CBF_REAL_D2T_INTERVAL_ROWS` は、別途厳密な到達管上で `h^(5)` の係数下限を**認証済み**の場合に限って、Bernsteinによる周期内 `h(s)>=0` の保守的な線形半空間へ変換できる関数。関数自身に区間上界を計算・認証する機能はない。誤差、次周期の低次条件継承、再帰的可行集合K、センサ、突然出る障害物も証明していない。

## 新規ファイル一覧

- `CBF_REAL_D2T_JET_SOURCE.m` — 拡張21状態、4階の物理ジェット。
- `CBF_REAL_D2T_OBSTACLE_EVAL_SOURCE.m` — 3D障害物バリアとpsi0..4。

- `CBF_REAL_D2T_THRUST_ROWS.m` — 25ms一定加速度モデルにおける推力0～20 Nの必要十分なddT上下界。
- `CBF_REAL_D2T_QP_ROWS.m` — 障害物＋推力波形範囲＋既存トルク箱の線形条件。

- `CBF_REAL_D2T_SELFTEST.m` — 物理モデルとの一致、短時間RK4、アフィン性、推力制約の解析解と極値計算の一致試験。

## MATLABでの独立実行例

`CBF_GENERATOR` フォルダを含む親ディレクトリから:

```matlab
addpath(genpath(fullfile(pwd,'CBF_GENERATOR')));
generate_CBF_REAL_D2T_OBSTACLE;
results = CBF_REAL_D2T_SELFTEST;
```

既存 `CBF_GENERATOR/COMMON/CBF_COMMON_MODEL.m` が参照される。追加ライブラリ不要で生成できるが、`CBF_REAL_D2T_SOLVE` には Optimization Toolbox が必要。MATLABをこの環境で実行できていないため、セルフテストのPASSや処理時間は未確認。

## Sim接続前に別途必要な設計

1. 推力 `T,Tdot` の状態を初期化・保持し、実入力へ正しく写像する物理的アクチュエータ／ZOH入力更新を確定（現在のSimは上の連続推力プロファイルを実装していない）。
2. 毎周期のHLC公称推力から `ddT_nom` を決める因果則、物理的な `ddT` 限界・レート限界を定義。トルクと推力の同時最適化、復帰時の目標補正器との相互作用を評価。
3. `CBF_REAL_INIT`、`CBF_REAL_DISPATCH`、新しいSCHEMESの方式番号登録を**合意後に別途**実施。現段階では一切変更しない。
4. 第5階下界の外向き丸め、サンプル間安全、次周期の低次psi継承、継続可能集合、障害物数に対する25ms実時間性を監査する。保証なき `continueBounded` 等を安全と呼ばない。
